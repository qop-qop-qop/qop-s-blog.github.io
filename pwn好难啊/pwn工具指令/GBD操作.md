# 内存查看

## 不同结构结构

| 查看 FILE 结构体 | `p/x *(struct _IO_FILE_plus*)地址` |
| ---------------- | ---------------------------------- |
| 查看虚表         | `p/x *(struct _IO_jump_t*)地址`    |
| 查看原始内存     | `x/100xg 地址`                     |
| 查看 main_arena  | `p/x *main_arena`                  |
| 自定义查看       | `define pio ... end`               |

## 编码查看

x /数量,格式,大小 地址

这里的单位 `b` 代表字节，`h` 代表半字（2字节），`w` 代表字（4字节），`g` 代表巨型字（8字节）。如果写 `x /10wx`，第一个 `w` 是数量，第二个 `w` 是单位。

这里可以熟悉什么样的格式就用什么样的。推荐还是g的格式。

# 主要操作指令

| 分类           | 命令示例                                 | 功能说明                                                     |
| :------------- | :--------------------------------------- | :----------------------------------------------------------- |
| **程序执行**   | `start`, `run [args]`                    | 启动程序，`start`会在程序入口点停下。                        |
| **断点与单步** | `break *0x地址`, `next`, `step`          | 与标准 GDB 一致。`next`（步入）和 `step`（步过）会智能跳过函数内部。 |
| **内存与指针** | `telescope $rsp 10`                      | **强力命令**。从指定地址（如栈顶 `$rsp`）开始，递归地打印出连续的指针链。 |
|                | `vmmap`                                  | 以彩色和更清晰的方式显示进程的内存映射（类似 `cat /proc/pid/maps`）。 |
|                | `search "字符串"` 或 `search 0xdeadbeef` | 在进程内存空间中搜索特定数据。                               |
| **漏洞分析**   | `checksec`                               | 快速查看目标二进制文件启用的安全机制（如 NX, ASLR, Canary）。 |
|                | `canary`                                 | 在栈上寻找并高亮显示 Stack Canary 的值。                     |
|                | `rop` / `ropper`                         | 在运行时查找当前进程中的 ROP gadgets。                       |
|                | `cyclic 200` / `cyclic -l 0x61616161`    | 生成或定位用于测试溢出点的特殊字符串模式，是溢出漏洞开发的关键工具。 |

# 搜索内存内容

- **搜索字符串**：`search "flag"` —— 在所有可读可写内存段搜索 ASCII 字符串。
- **搜索十六进制**：`search 0xdeadbeef` —— 搜索 4 字节值 `0xdeadbeef`。
- **限制搜索范围**：`search -m 0x602000 0x603000 0x90` —— 只搜索从 `0x602000` 到 `0x603000` 区间内的单字节 `0x90`（NOP 指令）。
